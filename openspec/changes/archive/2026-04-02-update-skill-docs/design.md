## Context

当前项目中有 5 个技能文档，但格式不统一、详细程度不一致：
- `baby-diary/SKILL.md`: 结构最完整，包含示例表格和代码示例
- `openspec-*` 系列技能：格式各异，缺少统一的参数说明和示例

**约束条件**:
- 仅更新文档，不修改代码
- 保持现有技能功能不变
- 文档格式需要向后兼容现有技能系统

## Goals / Non-Goals

**Goals:**
- 统一所有技能文档的格式结构
- 为每个技能添加清晰的使用示例
- 明确参数说明（必需/可选、类型、默认值）
- 添加技能类型说明和最佳实践

**Non-Goals:**
- 不修改技能的代码实现
- 不添加新的技能端点
- 不改变技能的触发机制

## Decisions

### 1. 采用 baby-diary 格式作为标准模板

**决策**: 以 `baby-diary/SKILL.md` 的格式为基础，作为所有技能文档的标准模板。

**理由**:
- baby-diary 格式最完整，包含所有必要元素
- 结构清晰：frontmatter → 简介 → 端点列表 → 使用示例 → 注意事项
- 包含表格形式的参数说明，便于快速查阅

**替代方案考虑**:
- 方案 A: 采用 openspec 官方模板 → 拒绝，过于简化，缺少示例
- 方案 B: 自定义新格式 → 拒绝，增加学习成本

### 2. 标准文档结构

**决策**: 所有技能文档采用以下结构：

```markdown
---
name: <skill-name>
description: <一句话描述>
license: MIT
compatibility: <依赖要求>
metadata:
  author: <作者>
  version: "<版本号>"
  generatedBy: "<生成来源>"
---

# <Skill Name> - <中文名称>

简介段落

## 可用的技能端点

### 1. <endpoint_name> - <中文名称>

**参数：** 表格形式

**示例：** 自然语言示例 + JSON 示例

## 使用方法

自然语言调用示例

## 注意事项

使用提示和限制
```

### 3. 参数表格格式

**决策**: 所有参数使用统一表格格式：

| 参数 | 必需 | 类型 | 默认值 | 说明 |
|------|------|------|--------|------|

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 文档更新后与代码实现不一致 | 在文档中添加"兼容性"说明，标注文档版本 |
| 技能系统缓存旧文档 | 需要重启 openclaw 或清除缓存 |
| 格式变更导致解析问题 | 保持 frontmatter 格式兼容 |
