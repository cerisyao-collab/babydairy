## Context

目前 OpenClaw 通过 Homebrew 和 npm 分发，仅支持本地安装。用户需要在远程服务器上部署 OpenClaw 以支持：
- 团队协作环境
- 云端开发环境
- 离线/内网环境

当前版本：`2026.3.23-2`

## Goals / Non-Goals

**Goals:**
- 创建可打包 OpenClaw 及其所有依赖的脚本
- 支持远程服务器部署（Linux/Unix）
- 支持离线安装包生成
- 简单的版本管理

**Non-Goals:**
- 不支持 Windows 远程服务器
- 不修改 OpenClaw 核心代码
- 不创建新的包管理器

## Decisions

### 1. 打包格式选择

**决策**: 使用 `.tar.gz` 格式

**理由**:
- Unix/Linux 系统原生支持
- 保持文件权限
- 压缩率高，传输效率高

**替代方案**:
- `.deb`/`.rpm`: 需要针对特定发行版，维护成本高
- `Docker 镜像`: 依赖 Docker 环境，不够轻量

### 2. 依赖处理

**决策**: 打包时包含所有 node_modules 依赖

**理由**:
- 远程服务器可能无法访问 npm registry
- 部署速度快，无需远程安装依赖

### 3. 部署方式

**决策**: 使用 `scp` + `ssh` 进行远程部署

**理由**:
- 无需额外工具
- 大多数服务器已预装 SSH

## Risks / Trade-offs

| Risk | Mitigation |
|------|------------|
| 远程服务器架构不同（如 ARM vs x86） | 在打包脚本中添加架构检查 |
| Node.js 版本不兼容 | 在安装包中包含 Node.js 版本要求说明 |
| 权限问题 | 提供详细的安装和权限配置说明 |

## Migration Plan

1. 本地构建远程安装包
2. 测试安装包在目标服务器上的安装
3. 验证功能正常
4. 更新文档
