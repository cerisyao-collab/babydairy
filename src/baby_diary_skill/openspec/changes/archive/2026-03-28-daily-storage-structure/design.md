## Context

当前宝宝日记技能使用月度文件存储记录，但随着记录增多，单文件可能超过 200KB，导致 AI 读取效率下降。需要改为按日存储，实现更细粒度的数据管理。

## Goals / Non-Goals

**Goals:**
- 按日分割存储，每日一个 JSON 文件
- 确保单文件大小 <200KB
- 创建日期索引支持快速查询
- 支持渐进式加载（按需读取特定日期）

**Non-Goals:**
- 不改变记录数据结构
- 不改变 API 接口
- 不删除历史数据

## Decisions

### 1. 存储结构
**Decision:** 使用扁平目录结构，按日命名文件

```
records/
├── index.json           # 日期索引
├── 2026-03-25.json      # 3 月 25 日记录
├── 2026-03-26.json      # 3 月 26 日记录
├── 2026-03-27.json      # 3 月 27 日记录
└── images/              # 图片存储
    └── *.jpg
```

**Rationale:**
- 扁平结构易于浏览和调试
- 日期命名直观，易于定位
- 索引文件小，加载快速

### 2. 索引格式
**Decision:** JSON 格式，按日期组织元数据

```json
{
  "version": "1.0",
  "updated": "2026-03-27T12:00:00Z",
  "days": {
    "2026-03-27": {
      "file": "2026-03-27.json",
      "count": 12,
      "sizeBytes": 4567,
      "types": ["feeding", "sleep", "bowel"]
    }
  }
}
```

### 3. 文件大小监控
**Decision:** 每日记录天然增长，单文件通常 <50KB

预估：
- 每条记录平均 200-500 字节
- 每日 10-20 条记录 = 2-10KB
- 即使密集记录（100 条/日）也远小于 200KB

### 4. 读取策略
**Decision:** 三阶段渐进式加载

1. **索引加载**: 读取 `index.json` 获取日期列表
2. **按需加载**: 根据查询加载特定日期文件
3. **范围查询**: 批量加载多个日期文件

## Risks / Trade-offs

**Risk:** 文件数量增加（365 文件/年）
→ **Mitigation:** 现代文件系统轻松处理，且 AI 只需读取索引

**Risk:** 迁移现有数据耗时
→ **Mitigation:** 迁移脚本一次性运行，支持断点续传

**Trade-off:** 文件数量 vs 加载效率
→ 选择效率优先，日度文件保证 AI 只读取需要的数据
